# Хук-гвардрейл против цепочек команд + forward-slash allow-правила

Сессия 2026-07-15. Два связанных фикса вокруг пермишенов Claude Code.

## Проблема 1: allow-правила с бэкслэшами не матчат вызовы Bash-tool

Матчинг пермишенов **буквальный**: `\` ≠ `/`. Правило вида
`Bash(...python.exe "C:\Users\RHL49\.claude\skills\...\gen_invoice.py" *)`
матчит только команду с **бэкслэшами**. Но **Bash-tool** нормализует пути в **прямые слэши** (`C:/Users/RHL49/...`), поэтому backslash-only правило не совпадает → промпт при каждом запуске. (PowerShell-tool исполняет с бэкслэшами, ему backslash-правила подходят.)

**Фикс:** каждому скилл-скрипту дали **два** Bash-правила — backslash + forward-slash двойник. Прошлись по всему Bash-блоку в `~/.claude/settings.json` (perms, jsoncheck, fetch_mail, preflight, read_pdf, cleanup, file_into, reconcile, xlsx_info, gen_quote, gen_invoice, search_docs, canonical_spending_report).

## Проблема 2: CLAUDE.md запрещает цепочки, но это не енфорсмент

Инструкция «не склеивай команды через `&&`/`;`/`|`, не ставь ведущий `cd`» жила только в CLAUDE.md — а это **мягкое указание модели**, которое она может нарушить. Allowlist тоже не блокирует цепочки: он гейтит лишь **тихий** прогон (при несовпадении показывает промпт, а не запрещает). Единственный жёсткий блок — `deny`-список, и там только деструктив. Итог: в одной из сессий реально выполнилась цепочка `cd … && python -c … && gen_invoice …` — allowlist спросил, кто-то подтвердил, и она прошла.

**Фикс — PreToolUse-хук как настоящий жёсткий гейт:**

- Скрипт `C:\Users\RHL49\.claude\hooks\block_chains.py`.
- Подключён в `~/.claude/settings.json` → `hooks.PreToolUse`, матчер `PowerShell|Bash`, **вторым** хуком рядом с логирующим (каждый хук получает свою копию stdin — логирование не пострадало, проверено).
- Читает JSON хука со stdin; если в команде на верхнем уровне есть `&&`/`||`/`;`/`|` (**quote-aware** — операторы внутри `'...'`/`"..."` не считаются) → `exit 2` с причиной в stderr → Claude Code блокирует вызов и возвращает причину модели, та переотправляет отдельными вызовами.
- **Исключение:** чистые git-цепочки, где каждый сегмент начинается с `git` и нет пайпа (`git add . && git commit … && git push`) — пропускаются (CLAUDE.md велит держать их вместе).
- Одиночный `cd X` разрешён; `cd X && …` ловится правилом про цепочки. Fail-**open** на любой ошибке парсинга — баг в хуке не заклинит тулинг.

**Последствие:** режутся и обычные пайплайны (`Get-ChildItem | Sort`, `grep x | tail`). Вместо них — инструмент Grep, `Get-Content -Tail`, или отдельные вызовы. Строгость правится в функции `verdict()`.

**Проверка при установке:** 14 юнит-тестов + живые тесты (цепочка блокируется, git-цепочка проходит, пайп блокируется, одиночная команда работает, логирование пишет) — всё зелёное.
