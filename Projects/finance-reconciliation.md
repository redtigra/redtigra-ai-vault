**Дата:** 2026-07-12

**Связано:** [[mail-forward-handover]], [[ms-graph-setup]]

## Зачем

`processing-log.html` фиксировал раскладку файлов, но не было связки «квота → PO → инвойс → оплачено». Из-за этого расхождения ловились постфактум (недобор CBRE €1,536; Canonical «26 дней не проинвойсено»; одна и та же фактура жила в 3 местах и рассинхронилась за день). Реестр + сверка это централизуют.

## Что построено (`~/.claude/skills/process-finance/`)

- **`reconcile.py`** — выводит `finance-ledger.csv` + `finance-reconciliation.html` из `processing-log.html`. HTML в фирменном стиле лога: KPI-карточки + секции ⚠ to-bill / ⛔ blockers / ✓ matched / payables / полный реестр с бейджами.
- Финальный шаг `process-finance` теперь запускает `reconcile.py` (отчёт обновляется сам).
- Allowlist для `reconcile.py` добавлен в `~/.claude/settings.json`.

### Ключевые решения
- **Реестр ВЫВОДИТСЯ из лога**, не ведётся параллельно → бэкфилл автоматический. Лог остаётся человекочитаемым журналом.
- **Гибрид:** чего в логе нет (тоталы PO, явный `po_ref`) — кладём в **`finance-ledger-enrichment.csv`** (по `doc_id`), он мёржится сверху и переживает пересборку.
- **Где живёт:** рядом с `processing-log.html` в личном OneDrive (`Documents\finance-docs-to-sort\`) — **НЕ** в `Company Documents - Operations` (сетевая шара, туда ничего).
- **Сумма в имени файла** — конвенция `-<CUR><amount>` последним полем, каноничный вид `EUR12558.00` (ISO-валюта, точка-десятичная, без разделителей тысяч). Причина: **имя переживает ручные перекладки** (заметка в логе устаревает — доказано кейсом Eusolve), и reconcile читает сумму из имени первой → уходит хрупкость regex по заметке (был баг: `$600` из заметки перебивал €378.50).

### Правила флагов (важные уточнения от пользователя)
- **PO > суммы = норма** (буфер «на всякий случай»), НЕ флаг.
- **INV > PO** = блокер (инвойс отклонят, нужен обновлённый PO).
- **PO < квоты** = недопокрытие.
- Наша квота ниже правильной ставки = недобор (потеря выручки; это про НАШУ цену, не про PO-буфер).
- Три разные вещи, которые легко смешать: PO-буфер / недопокрытие PO / недобор по квоте.
- FX: валюты (€/$) НЕ смешиваем, тоталы раздельно.

### Технические заметки по парсеру
- TYPE ищется по enum (не по позиции) — клиент/проект могут содержать дефисы (`T-Mobile`, `Montreal-PS9`).
- `po_key()` нормализует ref для матчинга: срезает префикс `PO` и ведущие нули → `PO7810`/`07810`/`PO 07810` и `95NLP…`/`PO95NLP…` схлопываются.
- identifier = последний токен, **не являющийся суммой** (иначе `-EUR12558.00` затирает номер PO; заодно `doc_id` у SINV стал `factuur99`, а не `EUR2129.60`).
- `guess_po_ref` — регистрозависимый `PO` (иначе ловил «po» в «re**po**rting»), только для INV/SINV.
- superseded-дубли (`…-superseded-…`) исключаются из сумм, но остаются в полном реестре.

## Субподрядчики — распознавание (ступень 1, сделано 2026-07-12, commit `876b55d`)

Скилл теперь сам классифицирует и относит субподряд-косты:
- **Issuer-тест** в skill.md делит наши `INV/SQ` от субподрядных `SINV/SubQ` (по «кто кому выставляет» + слову Invoice/Factuur/Rechnung vs Quote/Estimate/Offerte). `SubQ` → папка `30-SubQ`, `SINV` → `40-Subcontractors`.
- **vendor → client_account** через плоский **`finance-docs-to-sort\subcontractors.csv`** (~8 строк, руками). Колонки: `issuer_match` (имя/email, токены через `|`), `client_account`, `default_project`, `pay_entity` (IBAN/юрлицо — важно для Buardeti vs Ardeti), `note`. Засеян: Buardeti/Ardeti→CBRE(NL), Eusolve→ASK (Barcelona, аккаунт по джобу).
- `ASK` / нет матча → скилл **спрашивает** и предлагает дописать строку. Никогда не угадывает аккаунт.

**Почему НЕ конвейер вольт→frontmatter→build→JSON-кэш** (рассматривали, отвергли): оверинжиниринг под ~8 строк; кэш при ребилде-каждый-прогон = церемония; парсинг не убирается, а переносится; связывает скилл с путём вольта (хрупкая межрепная зависимость у пайплайна, читающего недоверенные PDF); frontmatter в прозе ломается человеком + дублирует данные внутри файла; «learn-on-tell», пишущий в вольт из инвойса = prompt-injection поверхность. Вывод — лестница сложности: ступень 0 «спрашивать», **ступень 1 «плоский csv» (тут)**, ступень 2 «генерация из вольта» — только когда вендоров станет ~30, а не 8. Вольт (`Partners and services/*.md`) остаётся человеческим источником; csv — маленькая явная выжимка, не синкается кодом.

## Осталось — заход A #2

**Margin-вид.** Связать выручку и субподряд-кост по одному джобу → `Revenue − Cost = маржа`. Загвоздка: идентификаторы разные (CP job `#8202601621` vs RH247 ticket `28735` vs дескриптор) — автоматом не сматчить, нужен явный **`job`-ключ** (проще всего в enrichment). Плюс FX (CP PO21380 **$600** — Connectivity Point US-компания, PO в долларах-буфере над €521.50-квотой RH247; кост Eusolve €378.50; маржа в `Eusolve.md` уже посчитана вручную = €143/27%).
