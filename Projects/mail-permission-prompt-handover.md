## Обновление 2026-07-08 — сужение прав + подтверждение узкой формы

В ходе security-аудита разрешений широкие python-правила были **убраны** (они авто-одобряли любой скрипт — дыра под prompt-injection, т.к. агент читает недоверенные PDF/письма). Вместо `PowerShell(...python.exe *)` (широкое, из решения ниже) введены **узкие per-script правила** в `settings.local.json`:

```
PowerShell(C:\Users\RHL49\AppData\Local\Python\pythoncore-3.14-64\python.exe "C:\Users\RHL49\.claude\skills\<skill>\<script>.py" *)
```

(в JSON-файле — одинарное экранирование `\\`, БЕЗ `&`, `*` отдельным токеном; то же правило, что предлагает сам Claude Code в `permission_suggestions.ruleContent`, только с ` *` вместо вшитых аргументов.)

**Подтверждено объективно через лог (не по наблюдению за промптами):** probe `xlsx_info.py <arg>` в этой форме дал `PRE_TOOL_USE` без последующего `PERMISSION_REQUEST` → промпта не было. Значит: (1) узкая per-script форма с закавыченным путём скрипта + хвостовой ` *` **матчит** (не только широкое exe-only правило); (2) `settings.local.json` перечитывается в рамках сессии (H1 повторно опровергнута).

**Метод самопроверки без наблюдения за промптами** (лог — объективный оракул, `PERMISSION_REQUEST` пишется ⟺ показан промпт):
```
grep "^=== PERMISSION_REQUEST" ~/.claude/permission-requests.log | tail
```
Добавлен хук `PostToolUse` → сигнатура «выполнилось молча» = `PRE_TOOL_USE` → `POST_TOOL_USE` без `PERMISSION_REQUEST` между ними.

**Важно:** прежняя память `feedback_powershell_permission_matching.md` одно время утверждала про **учетверённый** бэкслеш `\\\\` — это ОШИБКА, она вызывала регрессии. Верно **одинарное** экранирование `\\`, как в этом документе. Память исправлена 2026-07-08.

## Решение (итог)

**Корневая причина — комбинация двух факторов:**
1. **`& "путь"` (call-оператор) ломает wildcard-матчинг.** Подтверждена гипотеза H2 из черновика ниже. Правило `PowerShell(& "C:\...\python.exe" ... *)` никогда не матчило, независимо от экранирования бэкслэшей.
2. **Рабочая форма — одинарный бэкслэш, БЕЗ `&`, звёздочка отдельным токеном после пробела:**
   ```
   PowerShell(C:\Users\RHL49\AppData\Local\Python\pythoncore-3.14-64\python.exe *)
   ```
   (в JSON-файле это `\\` — одинарное экранирование, НЕ `\\\\`). Это опровергает прежнюю догадку из п.4 черновика — двойной бэкслэш был ошибкой, не решением.

**Как было подтверждено:** добавлены hooks `PermissionRequest` + `PreToolUse` (matcher `PowerShell|Bash`) в `~/.claude/settings.json`, пишущие весь stdin в `~/.claude/permission-requests.log`. Это дало объективный лог вместо догадок по выводу команды — запись `PRE_TOOL_USE` без последующей `PERMISSION_REQUEST` = правило сматчило, промпта не было. Так последовательно отсеяны три ложных варианта правила (glued-star без пробела, двойной бэкслэш, `&`-форма), пока не нашёлся рабочий. Лог остаётся в settings.json для диагностики будущих прецедентов.

**Практический эффект:** одно это правило покрывает **все** python-скрипты во всех скиллах (`.claude` и `.codex`), а не только `fetch_mail.py` — per-script правила (15 штук, см. ниже) избыточны, можно чистить.

**Побочное требование:** все `skill.md`/`SKILL.md`/`CLAUDE.md`, вызывающие python по полному пути, переписаны на голый путь без `&` (иначе выигрыш от правила теряется для новых вызовов):
- `~/.claude/skills/mail/skill.md`
- `~/.claude/skills/process-finance/skill.md`
- `~/CLAUDE.md` (xlsx-info)

**Гипотеза H1 (settings.json не перечитывается в рамках сессии) — опровергнута.** Правки применялись и матчились без перезапуска Claude Code в той же сессии (подтверждено логом).

## Что я менял по порядку — и где ошибался
1. **Добавил mail-правила** (прошлая сессия) в форме `\\\\` (двойной бэкслэш) → всё равно промпт.
2. **Схлопнул `\\\\` → `\\`** (одинарный), думая, что двойной — переэкранирование. **Ошибка** — превращает `\skills`→regex `\s`, `\fetch`→`\f`. Стало хуже.

## ⚠️ Критический изъян моей проверки
**Я НЕ вижу permission-промпты. Пользователь — видит.** С моей стороны команда, которая «выполнилась и дала вывод», неотличима между:
- (a) правило сматчило → промпта не было, или
- (b) пользователь вручную нажал **Yes** (разовое разрешение) → выполнилось один раз, правило не сохранилось.

Дважды я видел вывод `fetch_mail.py` и объявлял «работает» — но это почти наверняка был **случай (b)**: разовое одобрение. При повторном запуске той же команды снова промпт — чего не было бы, если бы правило матчило. **Значит, нет ни одного подтверждённого доказательства, что хоть одно моё рукописное правило в `settings.json` вообще сматчило.**

## Гипотезы (по убыванию вероятности)
**H1 — `settings.json` не перечитывается в рамках сессии (наиболее вероятно).** Claude Code обновляет in-memory allowlist мгновенно, когда *сам* пишет правило (путь «don't ask again» → `settings.local.json`), но мои *внешние* правки `settings.json`, вероятно, не перечитываются до перезапуска приложения. Это объясняет **все** наблюдения: ни одна моя правка среди сессии (в любой форме) не вступала в силу, поэтому всегда промпт, а единственные «успехи» — ручные одобрения. Если так — **текущее правило (строка 53) может уже быть корректным и просто требует перезапуска.**

**H2 — форма с call-оператором `& "..."` не токенизируется, поэтому `*` берётся буквально.** Если матчер для команд `& "quoted exe"` откатывается к точному сравнению строк, то точное правило приложения матчит, а мой ` *` никогда не работает как wildcard (нужен буквальный хвост ` *`). Тогда wildcard просто не работает для команд такой формы.

**H3 — экранирование под regex всё ещё чуть неверно.** Матчер трактует паттерн как regex (`$` работает как якорь конца — подтверждено). Литеральный `\` требует `\\`. Думаю, строка 53 теперь корректна по этому пункту, но чисто это не протестировано.

1. **Перезапустить Claude Code**, затем выполнить команду из раздела «Симптом».
   - Нет промпта → **H1 подтверждена**; текущее правило корректно, проблема была в перезагрузке. Готово.
   - Всё ещё промпт → продолжать.
2. В той же свежей сессии проверить **точную** форму приложения: добавить в `settings.json` правило, идентичное settings.local строке 54, но с сегодняшними аргументами, и запустить. Если точное работает, а ` *` нет → **H2 подтверждена** (wildcard непригоден для `& "..."`).
3. Если H2 — перевести скилл на форму с проверенным wildcard: вызывать через **Bash + forward-slash путь к python**, чтобы попасть под уже существующее правило `Bash(/c/Users/RHL49/.../python.exe *)` (строка 81).
