## 1. Цель и два слоя сложности

Отвязать существующий Claude Code ops-сетап от **рабочей Windows-машины** и перенести на
личный **Linux-ноутбук**. Это кросс-ОС миграция. Два очень разных по объёму слоя:

- **Слой 1 — система харденинга (`harden-skill` + scan + Stop-хук).** На Linux **проще**, чем на
  Windows (см. §2). Умеренный объём: OS-абстракция двух скриптов + `bootstrap.py`.
- **Слой 2 — ops-скиллы (invoice/quote/mail/process-finance/docx-render-check).** Настоящая гора:
  завязаны на Word COM / `pywin32` / OneDrive / рендер docx через настоящий Word. Отдельный
  крупный проект ре-платформирования (см. §4). **Не** часть harden-переносимости.

**Уже сделано (2026-07-21):** harden-skill скрипты **само-локализованы** — пути вычисляются в
рантайме (`expanduser("~")`, `dirname(__file__)`, `sys.executable`), хардкода `C:\Users\RHL49`
в них больше нет. Это Windows-безопасный фундамент; на Linux сами `.py` поедут без правок.
Коммит `b5a903f` в `redtigra-claude`.

## 2. Linux не добавляет сложность, а УБИРАЕТ

Ключевой инсайт: большая часть Windows-машинерии на Linux не нужна.
- **Нет обратных слэшей** в путях → отпадает вся комбинаторика слэшей.
- **Нет инструмента PowerShell** (только Bash/шелл) → правила не двоятся PowerShell/Bash.
- Итог: allow-правило схлопывается с **8–16 комбинаций до ОДНОГО** `Bash(python3 /path/script.py *)`.
- Уходит и специфика: `&`-запрет, удвоённые `\\`, Store-stub Python, полный путь к exe.

Что из-за этого меняется в коде (Слой 1):
- **`gen_rules.py`** — добавить ветку по ОС: на POSIX печатать одно правило `Bash(<sys.executable> "<script>" *)` (без slash-комбинаций, без PowerShell). Ядро (`--from-log`, формат) остаётся.
- **`match_rule.py`** — сегментные эвристики переписать на bash-флейвор (`|`, `&&`, `;`, `$(...)`, backticks) вместо PowerShell-подвыражений; сам glob-матч и парсер правил ОС-нейтральны.
- **`scan.py` / `log_event.py` / `log_report.py` / `copy_skill.py`** — уже ОС-нейтральны после само-локализации (только пути, а они через `os.path`).

## 3. `bootstrap.py` — «одна команда на новом хосте»

Скрипт-установщик, запускается один раз после клонирования репозитория скиллов:
1. Определяет `sys.executable` и `HOME` текущего хоста.
2. Для каждого скилла с python-скриптом гоняет ОС-aware `gen_rules` и **мёржит** правила в
   `~/.claude/settings.json` (идемпотентно — не плодить дубли).
3. (Пере)ставит `Stop`-хук в `settings.json`. Тело хука (`… scan.py --commit >/dev/null 2>&1 || true`)
   уже POSIX-переносимо — меняются только пути exe/скрипта.
4. Сверяет/чинит абсолютные пути в примерах вызова внутри `SKILL.md` (или сделать их
   плейсхолдерами, стампуемыми bootstrap'ом).
Тогда перенос = `git clone` репозитория скиллов + `python3 bootstrap.py`.

Открытый вопрос: путь бэкап-репозитория (`~/repos/redtigra-claude`) — сейчас по конвенции;
на новом хосте подтвердить/сделать параметром bootstrap.

## 4. Ре-платформирование ops-скиллов (оценка, отдельный проект)

Высокоуровнево, НЕ в объёме harden-переносимости. Блокеры:
- **Word COM / `pywin32` / `docx-render-check`** (рендер docx через настоящий Word) → LibreOffice
  headless (`soffice --convert-to pdf`); переписать генерацию/проверку docx. Самый большой кусок.
- **OneDrive-пути** (`OneDrive - Remotehands 247 B.V\...`) → локальный/синхронизируемый эквивалент;
  решить, как папки Operations живут на Linux.
- **Микрософт-специфика в `/mail`** (Graph API — кросс-платформенный, скорее ОК; проверить auth-флоу).
- `xlsx-info`, `search-docs` — python-only (openpyxl/pdfplumber/python-docx), скорее переносимы.
Порядок и объём этого блока оценить отдельно, когда дойдёт.

## 5. Порядок операций (когда дойдёт до миграции)

1. На Linux-ноуте базовая точка: Claude Code, Python 3, git. (Подтвердить, что есть.)
2. Слой 1: дописать ОС-ветки в `gen_rules`/`match_rule` + `bootstrap.py` (строится на Windows, тестируется на Linux).
3. Клонировать репозиторий скиллов, `python3 bootstrap.py` → harden/scan/хук живут на Linux.
4. Слой 2 (отдельно): ре-платформирование ops-скиллов по §4.
5. Финально — отвязать от рабочей машины (перенести/пересоздать данные Operations).
